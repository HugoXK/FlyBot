A Workflow node's `tools` field names the connectors its run Bot may use, and the Settings node inspector now says so: the editable `Tools` field stays and a note under it explains that `github` grants `mcp__github__*`, `composio` grants the Composio connector, file and shell access is always full like a normal Bot, and a node that names no connector gets none. The README, the `define_workflow` tool description and the subsystem doc say the same; applying `tools` in the spawn path is a separate change that is not merged yet, so until it lands every connector stays refused ([#1520](https://github.com/ThinkFlowLab/FlyBot/issues/1520)).
