Merging on the code fork is now refused by GitHub, not by a script somebody remembered to run: a new required check, `enqueue-guard`, is written onto every pull request head from the same decision `node .github/scripts/enqueue-guard.mjs --pr <n>` prints — a `hold`, a tip with no PASS naming it, a PASS that lists no `Ran:`, a missing `agent-pr` or a body that names no issue all turn it red, and it flips green without a new commit when the label or the conclusion arrives. `.github/agent/merge-gate-ruleset.json` is the ruleset that requires it next to `tests-ok` (branch `refs/heads/main`, `bypass_actors: []`, strict checks off so every open pull request does not have to rebase); `node .github/scripts/gate-ruleset.mjs --check` reports the live state and `--rollback` removes it ([#812](https://github.com/ThinkFlowLab/FlyBot/issues/812)).
